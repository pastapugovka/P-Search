**Поисковый backend, который я использую у себя и решил выложить в портфолио**

## 🚀Быстрый запуск

```bash
git clone https://github.com/pastapugovka/P-Search.git
cd P-Search
bun install
bun run dev
```

Сервис поднимется на `http://localhost:3000` и сразу получит 38 демонстрационных документов для обучения.

```bash
curl "http://localhost:3000/api/health"
curl "http://localhost:3000/api/search?query=поиск"
```

> [!NOTE]
> Индекс собирается из ваших данных за ~10 мс при каждом запуске — подготовка не требуется.

## 🧠Учится на данных приложения

P-Search не знает вашего сайта заранее и самостоятельно изучает его содержимое. Доступны два режима:

- **🗃️ Режим 1 · Только данные из набора** — словарь, основы слов и подсказки собираются исключительно из файла `SEARCH_DATA`. Результат предсказуем
- **📊 Режим 2 · Данные плюс обучение на поисковых запросах** — движок запоминает, что и как ищут пользователи: частые запросы всплывают в подсказках первыми, «Возможно, вы имели в виду…» точнее понимает формулировки, ранжирование приближается к реальным привычкам

Режим задаётся в `.env`:

```env
SEARCH_LEARN=dataset
SEARCH_LEARN=queries
```

Возможности обучения в обоих режимах:

- Строит словарь по реальному контенту и запоминает, какие слова встречаются чаще
- Приводит слова к основам (RU/EN) и понимает формы: «поиск», «поиском», «поисковый»
- Предиктивные подсказки берутся **из ваших данных**, а не из заготовленного списка
- «Возможно, вы имели в виду…» подстраивается под ваш словарь и прощает опечатки

## 📖Терминология

- **Хит** — документ, в котором найдено хотя бы одно вхождение слов запроса
- **Пересечение результатов** — поиск документов, где встречаются все слова через `+`
- **Исключение из результатов** — удаление документов со словами через `-`
- **Категория** — кластер корпуса документов (поле `category`)
- **Тег** — маркер документа для навигации (поле `tags`)
- **Ключевые слова** — слова, по которым хит получает наивысший ранг (поле `keywords`)

## ⚙️Использование

1. Установите зависимости: `bun install` (или `npm install`)
2. Запустите сервис: `bun run dev` (или `npm run build && npm start`)
3. Проверьте статус: `curl "http://localhost:3000/api/health"`

Из коробки доступны 38 демонстрационных документов, и поиск обучается на них сразу после запуска.

## 📥Настройка сбора данных

1. Укажите источник в `.env`: `SEARCH_DATA=./data/контент-моего-сайта.json`
2. Подготовьте документы в простом формате
3. Подключите дополнительные источники через панель «/P»

Каждый документ — простой JSON:

```json
{
  "id": "docker-intro",
  "title": "Docker: контейнеры для вашего приложения",
  "content": "Docker упаковывает приложение вместе с окружением в образ.",
  "keywords": ["docker", "контейнеры"],
  "tags": ["docker", "devops"],
  "category": "инфраструктура",
  "link": "/guide/docker/intro"
}
```

`keywords` — ассистент ранжирования: совпадение по ключевому слову поднимает документ выше. `category` и `tags` — фильтры контекста «@» и «#».

> [!IMPORTANT]
> Изменили данные? Перезапустите сервис — индекс перестроится за миллисекунды.

## 📦Данные для обучения поиска

**Что участвует в обучении.** Только корпус документов, а в режиме `queries` — ещё и статистика поисковых запросов. Ничего другого движок не использует.

**🗂️ Где хранится обучение:**

- Корпус документов: путь через `SEARCH_DATA`, по умолчанию `data/search-content.json`
- Бэкапы обучения: **включены по умолчанию** — словарь, частоты, статистика запросов и сам корпус сохраняются в базу данных
- Настройка через `.env`: локальная база `DATABASE_URL` (PostgreSQL через Prisma) или облачная — VK Cloud, Яндекс Облако, Cloud.ru, Google Cloud, AWS, MongoDB Atlas, Neon, Supabase, Redis, Turso Cloud, Upstash, MotherDuck, Convex
- При запуске обучение восстанавливается из базы — **оно переживает остановку сервиса**
- Если бэкапы отключены (`SEARCH_BACKUP=false`) — обучение живёт только в памяти: при остановке сбрасывается полностью, при запуске индекс пересобирается из корпуса за ~10 мс

**🔁 Экспорт и импорт набора данных:**

- **Экспорт** — сохранить текущий набор документов в JSON: `/export` в палитре или `GET /api/dataset`
- **Импорт** — загрузить набор из JSON: `/import` в палитре или `POST /api/dataset`, либо указать файл через `SEARCH_DATA`

**🔄 Откат и сброс обучения:**

- Бэкапы включены (по умолчанию): откат к последнему сохранённому состоянию — `/restore` в палитре или `POST /api/restore`, данные достаются из базы
- Бэкапы отключены: сброс полный — остановка сервиса очищает обучение, перезапуск строит свежий индекс из `SEARCH_DATA`
- Начать с чистого корпуса: измените путь в `SEARCH_DATA` или отредактируйте файл
- Вернуть демонстрационный набор: восстановите `data/search-content.json` из репозитория

## 🎨Палитра команд «/»

Символ `/` в строке поиска открывает палитру быстрых команд: навигация — стрелки, выполнение — `Enter`, закрытие — `Esc`.

- `/help` — справка · `/clear` — очистить запрос и результаты · `/history` — история запросов
- `/export` — экспорт набора данных в JSON · `/import` — импорт набора из JSON
- `/backup` — сохранить бэкап обучения · `/restore` — откатить обучение к последнему бэкапу
- `/lang` — язык интерфейса · `/theme` — светлая, тёмная и авто-тема · `/bot` — боты и их команды

Команды ботов появляются в палитре **автоматически** после привязки — см. «🤖Боты».

> 💡 Полный список команд, API-эндпоинтов, переменных окружения и скриптов — в [**`COMMANDS.md`**](./COMMANDS.md).

## 🔌Провайдеры «/P» — выбор модели

`/P` подключает внешние модели и источники данных: **75+ провайдеров, включая Claude, GPT, Gemini**. После подключения модель доступна в любом клиенте.

1. Откройте `/P` и выберите провайдера из каталога
2. Укажите ключ (`--source`) и модель (`--model`)
3. Подключите через `--sync` (сразу) или `--async` (в фоне); отключение — `/P --disconnect anthropic`

```bash
/P anthropic --source sk-ant-xxx --model claude-3-5-sonnet --async
/P openai   --source sk-xxx     --model gpt-4o            --async
/P google   --source AIza-xxx   --model gemini-1-5-pro    --async
```

Флаги: `--source` (путь или API-ключ) · `--model` (модель) · `--format` (`json`/`csv`/`xml`/`api`) · `--sync`/`--async` · `--disconnect`.

## 🔮Предиктивный поиск и ИИ-режим

- **Предиктивный поиск** — подсказки по мере ввода, обученные на вашем контенте
- **ИИ-режим** — движок готовит контекст из топ-документов, а подключённая модель отвечает на его основе: RAG «поиск + генерация»

Модель подключается один раз в панели «/P» и затем работает в любом клиенте.

## 🧭Контекст «@»

Символы `@` и `#` сужают поиск до категории и тегов: подсказки выпадают сразу после ввода, выбранные значения становятся чипами. Два режима работы:

- **1 · Поиск с добавленным контекстом** — контекст добавляется к запросу: категория и теги фильтруют выдачу
- **2 · Поиск на основе контекста** — контекст становится основой запроса: сначала уточняются категория и теги, затем слова дополняют результат

```text
@категория              → поиск только в категории
#тег                    → поиск только по тегу
@категория #тег         → комбинированный фильтр
@инфраструктура docker  → docker в категории «инфраструктура»
#поиск стемминг         → стемминг среди документов с тегом «поиск»
```

Режим контекста выбирается в настройках клиента.

## 🤖Боты

Привязка бота добавляет его команды в палитру «/» у любого клиента — без перезапуска фронтенда.

1. Запустите бота на Bun, Python, Node.js или Discord.js
2. Привяжите его одной командой API — команды сразу появятся в палитре «/»

```bash
curl -X POST "http://localhost:3000/api/bots" \
  -H "Content-Type: application/json" \
  -d '{"name":"мой-бот","platform":"discord","commands":["/search","/stats"]}'
```

Или через `.env` — `BOT_NAME=мой-бот` — и команды бота появятся автоматически.

## 🔗API и настройка всего

Все запросы — на `http://localhost:3000/api/…`:

- `GET/POST /api/search` — поиск · `GET /api/suggest` — подсказки по префиксу · `GET /api/context` — категории, теги, статистика
- `GET /api/documents` — документы с фильтрами · `GET /api/providers` — каталог провайдеров
- `GET/POST /api/dataset` — экспорт / импорт набора данных · `POST /api/backup` — сохранить бэкап обучения · `POST /api/restore` — откатить к бэкапу
- `GET/POST/DELETE /api/bots` — боты · `GET /api/health` — статус сервиса

Параметры запроса: `limit` · `category`/`tags` · `fuzzy` · `lang` (`auto`/`ru`/`en`).

Операторы: `+обязательное` · `-исключить` · `"фраза"` · `@категория` · `#тег`.

Настройка движка — через `.env`:

```env
SEARCH_DATA=./data/search-content.json
DATABASE_URL=postgres://user:pass@localhost:5432/psearch
SEARCH_LEARN=dataset
SEARCH_BACKUP=true
SEARCH_TITLE_WEIGHT=5.0
SEARCH_KEYWORDS_WEIGHT=2.5
SEARCH_BODY_WEIGHT=1.0
SEARCH_K1=1.2
SEARCH_B=0.75
SEARCH_LIMIT=20
SEARCH_SNIPPET_WIDTH=42
SEARCH_MAX_FRAGMENTS=2
SEARCH_MARK_TAG=mark
SEARCH_LEVENSHTEIN_LIMIT=2
SEARCH_FUZZY=true
SEARCH_LANG=auto
```

Каждый параметр меняется на лету — без правки кода.

## ☑️Частые вопросы

- **Почему так быстро?** Индекс живёт в памяти и строится за ~10 мс, запрос выполняется за **0.1–1 мс**. Дисковых обращений нет
- **Сохраняется ли обучение при остановке сервиса?** Да: бэкапы включены по умолчанию, и всё хранится в базе данных — локальной Postgres/Prisma (`DATABASE_URL`) или облачной. При запуске обучение восстанавливается. Если отключить бэкапы — сброс полный
- **Как поменять данные?** Отредактируйте файл из `SEARCH_DATA` (или укажите новый путь) и перезапустите сервис, либо импортируйте набор через `/import` или `POST /api/dataset`
- **Как подключить поиск к своему приложению?** REST API напрямую (`/api/search`) или типизированный SDK в `src/lib/client` — в браузере, на сервере и в десктопе
