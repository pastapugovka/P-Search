# P-Search

**Поисковый backend, который я использую у себя и решил выложить в портфолио**

Два режима обучения · сам собирает контент · API с настройкой всего

## ⚡Ключевые преимущества

- Индекс в памяти: сборка ~10 мс, запрос **0.1–1 мс**, без дисковых обращений

- Нечёткий поиск: опечатки и неправильная раскладка

- Стемминг RU/EN и фильтр стоп-слов

- Предиктивные подсказки по мере ввода

- ИИ-режим RAG: контекст из найденного + ответ модели

- Обучение в двух режимах: только данные набора или данные + запросы

- Подключение 75+ провайдеров (Claude, GPT, Gemini и другие)

- Настройка через `.env` и параметры запроса

- Сборка и работа внутри контейнера

## 🚀Быстрый запуск

**Развернуть через Docker:**

```bash
git clone https://github.com/pastapugovka/P-Search.git
cd P-Search
docker compose up -d --build
```

По умолчанию по скрипту поднимается поиск с **SQLite** — всё готово сразу. Останавливается всё одной командой: `docker compose down`.

**Запустить локально:**

```bash
git clone https://github.com/pastapugovka/P-Search.git
cd P-Search
bun install
bun run dev
```

Сервис поднимется на `http://localhost:3000` с 38 демонстрационными результатами поиска.

**Проверьте работу:**

```bash
curl "http://localhost:3000/api/health"
curl "http://localhost:3000/api/search?query=поиск"
```

> [!NOTE]
> По умолчанию во всех вариантах запуска (локально и Docker) обучение хранится в **s-db** (SQLite). Для серьёзной нагрузки смените её на PostgreSQL или облачную базу — инструкция ниже.

## 🔗REST API

Все запросы — на `http://localhost:3000/api/…`. Методы, параметры и примеры каждого эндпоинта — в [**`API.txt`**](./API.txt).

**Поиск и подсказки:**

- `GET/POST /api/search?query=…` — полнотекстовый поиск · параметры: `query`, `limit`, `category`, `tags`, `fuzzy`, `lang`

- `GET /api/suggest?query=…` — предиктивные подсказки · параметры: `query`, `limit` (по умолчанию 8)

- `GET /api/context` — категории, теги и статистика индекса

- `GET /api/documents` — результаты поиска (корпус) · параметры: `limit`, `offset`, `category`, `tag`

**Данные и обучение:**

- `GET /api/dataset` — экспорт набора в JSON · `POST /api/dataset` — импорт набора из JSON

- `POST /api/backup` — сохранить бэкап обучения · `POST /api/restore` — откат к последнему бэкапу

**Провайдеры и боты:**

- `GET /api/providers?group=…&query=…` — каталог провайдеров

- `GET/POST /api/bots` — список и привязка ботов · `DELETE /api/bots/:name` — отключить бота

**Сервис:**

- `GET /` — справочник всех эндпоинтов · `GET /api/health` — статус сервиса

Параметры поиска: `limit` · `category`/`tags` · `fuzzy` · `lang` (`auto`/`ru`/`en`). Операторы: `+обязательное` · `-исключить` · `"фраза"` · `@категория` · `#тег`.

Типизированный клиент для любого клиента/сервера — `createClient` из `src/lib/client` (модели ответов — в `src/lib/client/types.ts`).

```bash
curl "http://localhost:3000/api/search?query=docker&limit=5&lang=ru"
curl "http://localhost:3000/api/suggest?query=пои&limit=5"
curl -X POST "http://localhost:3000/api/backup"
```

## 🧠Обучение на данных

P-Search самостоятельно изучает содержимое вашего сайта. Два режима:

- **🗃️ Только данные из набора** — словарь, основы и подсказки собираются из `SEARCH_DATA`; результат предсказуем

- **📊 Данные + обучение на запросах** — движок запоминает, что и как ищут: частые запросы всплывают первыми, «Возможно, вы имели в виду…» точнее понимает формулировки

Режим задаётся в `.env`: `SEARCH_LEARN=dataset` или `SEARCH_LEARN=queries`. Статистика обучения доступна через `GET /api/context`.

В обоих режимах обучение строит словарь по реальному контенту, приводит слова к основам (RU/EN), берёт подсказки **из ваших данных** и прощает опечатки.

## 📥Настройка сбора данных

1. Укажите источник в `.env`: `SEARCH_DATA=./data/контент-моего-сайта.json`

2. Подготовьте результаты поиска в простом формате

3. Импортируйте набор через `POST /api/dataset` или подключите источники через `/P`

Каждый результат поиска — простой JSON:

```json
{
  "id": "docker-intro",
  "title": "Docker: контейнеры для вашего приложения",
  "content": "Docker упаковывает приложение вместе с окружением в образ.",
  "keywords": ["docker", "контейнеры"],
  "tags": ["docker", "devops"],
  "category": "инфраструктура",
  "link": "/guide/docker/intro"
}
```

`keywords` — ассистент ранжирования, `category` и `tags` — фильтры поиска через операторы «@» и «#».

> [!IMPORTANT]
> Изменили данные? Перезапустите сервис — индекс перестроится за миллисекунды.

## 📦Данные и бэкапы

- **Корпус** — `SEARCH_DATA`, по умолчанию `data/search-content.json`

- **База по умолчанию** — **s-db** (SQLite) во всех вариантах запуска: локально и в Docker

- **Бэкапы включены по умолчанию**: словарь, частоты, статистика запросов и корпус сохраняются в базу

- **Обучение переживает остановку сервиса** и восстанавливается при запуске

- **Отключить бэкапы**: `SEARCH_BACKUP=false`

**При отключённом бэкапе данные не теряются:** переключение `SEARCH_BACKUP=false` не удаляет корпус, индекс и накопленное обучение — просто приостанавливается запись в базу. Включили бэкапы обратно — сохранение продолжится с того же места.

**Настройки базы защищены:** пользователь, база, пароль и ключи хранятся только в `.env` (папка не попадает в git) или в переменных окружения контейнера — секреты не светятся в репозитории и в коде.

Экспорт и импорт набора: `GET/POST /api/dataset`. Откат: бэкапы включены — `POST /api/restore` откатывает к последнему состоянию из базы; отключены — данные не теряются, просто откат недоступен.

> 📄 Пошаговая настройка локальных и облачных баз — в [**`DATABASE.md`**](./DATABASE.md): Redis, PostgreSQL, PostgreSQL отдельно и AWS по шагам.

## 🗄️База данных: полная настройка

**По умолчанию — SQLite (s-db)** во всех вариантах запуска: ничего настраивать не нужно, файл базы живёт в каталоге данных и поднимается вместе с поиском.

**Смена на PostgreSQL:**

1. Установите PostgreSQL и создайте пользователя с базой

2. Впишите строку подключения в `.env`:

```env
DATABASE_URL=postgres://user:pass@host:5432/dbname
```

3. Перезапустите сервис — бэкапы продолжат сохраняться в новой базе

**Docker:** PostgreSQL поднимается рядом одной командой и поиск сразу переключается на неё:

```bash
docker compose --profile db up -d --build
```

Пользователь, пароль и имя базы — `DB_USER`, `DB_PASSWORD`, `DB_NAME` в `.env` (есть значения по умолчанию, ничего в коде).

**Подключение облачных провайдеров:**

1. Выберите провайдера: VK Cloud, Яндекс Облако, Cloud.ru, Google Cloud, AWS, MongoDB Atlas, Neon, Supabase, Redis, Turso Cloud, Upstash, MotherDuck, Convex

2. Создайте базу в консоли провайдера

3. Скопируйте строку подключения и вставьте её в `DATABASE_URL` в `.env`

4. Перезапустите сервис — поиск подхватит облачную базу

Все настройки (пользователь, база, пароль, ключи) передаются только через `.env` или переменные окружения контейнера — защищены и не попадают в репозиторий. Полный список провайдеров и моделей — в [**`MODELS.txt`**](./MODELS.txt).

## 🎛️Команды через API

Все команды палитры «/» реализованы на уровне движка как вызовы REST API — клиенты лишь вызывают эндпоинты, ядро делает всё остальное.

**Работа с поиском:**

- `/help` → `GET /` — справочник всех эндпоинтов

- `/clear` → `GET /api/search` — новый запрос очищает выдачу

- `/history` → `GET /api/context` — статистика запросов

**Данные и обучение:**

- `/export` → `GET /api/dataset` — экспорт набора в JSON

- `/import` → `POST /api/dataset` — импорт набора из JSON

- `/backup` → `POST /api/backup` — сохранить бэкап обучения

- `/restore` → `POST /api/restore` — откат к последнему бэкапу

**Язык и настройки:**

- `/lang` → параметр `lang` (`auto`/`ru`/`en`)

- `/settings` → `GET /api/context` + переменные `.env`

- `/bot` → `GET/POST/DELETE /api/bots` — боты и их команды

Команды ботов появляются в палитре **автоматически** после привязки через `POST /api/bots` — см. «🤖Боты».

## 🔌Провайдеры «/P» — выбор модели

`/P <провайдер> --source <ключ> --model <модель>` подключает модели и источники данных. Реализовано на уровне движка: каталог доступен через `GET /api/providers`, модели — в [**`MODELS.txt`**](./MODELS.txt).

```bash
/P anthropic --source sk-ant-xxx --model claude-3-5-sonnet --async
/P openai   --source sk-xxx     --model gpt-4o            --async
/P google   --source AIza-xxx   --model gemini-1-5-pro    --async
```

Флаги: `--source` (ключ или путь) · `--model` (модель) · `--format` (`json`/`csv`/`xml`/`api`) · `--sync`/`--async` · `--disconnect`.

## 🔮Предиктивный поиск и ИИ-режим

- **Предиктивный поиск** — подсказки по мере ввода, обученные на вашем контенте: `GET /api/suggest`

- **ИИ-режим** — движок готовит контекст из топ-результатов поиска, а модель отвечает на его основе: RAG «поиск + генерация»

Модель подключается один раз в «/P» и работает в любом клиенте.

## 🧭Поисковые операторы

`@` и `#` сужают поиск до категории и тегов, `+` и `-` управляют обязательностью слов, `"фраза"` — точная фраза — это синтаксис параметра `query`. Два режима контекста:

- **1 · С добавленным контекстом** — контекст добавляется к запросу и фильтрует выдачу

- **2 · На основе контекста** — контекст становится основой запроса, слова дополняют результат

```text
@инфраструктура docker  → docker в категории «инфраструктура»
#поиск стемминг         → стемминг среди результатов с тегом «поиск»
+контейнер -docker      → контейнер, но без docker
"поисковый бэкенд"      → точная фраза
```

## 🤖Боты

Привязка бота добавляет его команды в палитру «/» у любого клиента — реализовано через API движка (`/api/bots`).

1. Запустите бота на Bun, Python, Node.js или Discord.js

2. Привяжите одной командой — и команды сразу появятся в палитре:

```bash
curl -X POST "http://localhost:3000/api/bots" \
  -H "Content-Type: application/json" \
  -d '{"name":"мой-бот","platform":"discord","commands":["/search","/stats"]}'
```

Или `BOT_NAME=мой-бот` в `.env` — команды появятся автоматически.

## ☑️Частые вопросы

- **Почему так быстро?** Индекс в памяти: сборка ~10 мс, запрос **0.1–1 мс**, без дисковых обращений

- **Обучение сохраняется при остановке?** Да: бэкапы включены по умолчанию, данные в базе (локальной Postgres/Prisma или облачной) восстанавливаются при запуске. Без бэкапов данные тоже не теряются — они просто не пишутся в базу, откат через `POST /api/restore` недоступен

- **Как поменять данные?** Отредактируйте `SEARCH_DATA` (или путь) и перезапустите, либо импортируйте набор через `POST /api/dataset`

- **Как подключить к своему приложению?** REST API (`/api/search`) или типизированный SDK в `src/lib/client` — браузер, сервер, десктоп
